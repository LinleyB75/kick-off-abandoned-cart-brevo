# Data design: Kick Off abandoned cart (test version)

The values your application sends to Brevo with the email. This table is generated by `npm run data-design` from the settings file and the email itself, and the same rules are checked before anything is sent.

## The values

| Value | Required | What it is | Rules | Example |
| --- | --- | --- | --- | --- |
| `firstName` | Optional | The customer's first name. Without it the heading reads "Your Cart... below". | Text, up to 40 characters. | `Alex` |
| `productName` | Required | The product in the cart, as it should be shown. Also the picture's alt text. | Text, up to 120 characters. | `Kick Off Your English Ebook CAT01` |
| `productImageUrl` | Required | The https address of the product picture. | An https address, no spaces, up to 2000 characters. No username or credential in it. | `https://res.cloudinary.com/xrzqkwov/image/upload/Screenshot_2024-04-04_094501.png` |
| `price` | Required | Sent exactly as it should be shown, with the currency, for example "$19.99 AUD". The application knows the currency and the format. | Text, up to 30 characters. It must contain a number, for example $19.99 AUD. | `$19.99 AUD` |
| `quantity` | Required | A whole number. | Text, up to 3 characters. It must be a whole number from 1 to 999. | `1` |
| `cartUrl` | Required | The https address that takes the customer back to their cart. Used by the Return to Your Cart button, and by the Outlook version of it. | An https address, no spaces, up to 2000 characters. No username or credential in it. | `https://shop.example.test/cart/restore?cart=TEST-0001` |

## Rules for every value

- Every value is sent as text, including numbers.
- No text value may contain `<` or `>`, or Brevo tags such as `{{` or `{%`, so a value can never change the email. The two addresses have their own rules, above.
- No text value may contain anything that looks like a card number.
- No text value may contain anything that looks like a Brevo key.
- The whole `params` object must stay under 100 KB, which is Brevo's limit.
- Leaving an optional value out, or sending it empty, is fine. The email still reads correctly.

## The request

`templateId` is the ID of the email in your Brevo account. The values below are made up.

```json
{
  "to": [
    {
      "email": "customer@example.test",
      "name": "Alex"
    }
  ],
  "templateId": 12,
  "params": {
    "firstName": "Alex",
    "productName": "Kick Off Your English Ebook CAT01",
    "productImageUrl": "https://res.cloudinary.com/xrzqkwov/image/upload/Screenshot_2024-04-04_094501.png",
    "price": "$19.99 AUD",
    "quantity": "1",
    "cartUrl": "https://shop.example.test/cart/restore?cart=TEST-0001"
  }
}
```

`npm run send:dry` prints this request and sends nothing. `npm run send:sandbox` checks it with Brevo and sends nothing.
